## Estrutura do repositorio

Pastas principais do projeto:

- `article/`: artigo cientifico construído incrementalmente a cada sprint.
- `app/`: aplicacao do dashboard.
- `data/`: dados brutos, processados e artefatos intermediarios.
- `docs/`: documentacao de apoio, incluindo canvas, backlog e atas.
- `models/`: modelos treinados e artefatos de avaliacao.
- `notebooks/`: notebooks de experimentacao.
- `src/`: codigo-fonte para ETL, ML, geoespacial e dashboard.
- `tests/`: testes unitarios, de integracao e de aceitacao.
- `.github/`: automacoes, templates e configuracoes do GitHub Projects.

## Backlog e organizacao

O backlog inicial do projeto esta documentado em [docs/backlog.md](docs/backlog.md). Ele organiza as issues por epico, milestone e labels para cobrir a base do repositório, a engenharia de dados, o fluxo de ML, a camada geoespacial, o dashboard e o deploy.

## Fluxo previsto

O repositorio foi organizado para sustentar este fluxo de trabalho:

1. Estrutura inicial e planejamento.
2. Coleta, limpeza e integracao dos dados.
3. Feature engineering e modelagem.
4. Analise geoespacial e geracao de hotspots.
5. Dashboard e publicacao da aplicacao.
